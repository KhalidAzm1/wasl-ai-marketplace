# مساعد المنتج وتحليل الأعمال

> يحوّل الفكرة أو المتطلب الأولي إلى تحليل أعمال وقصص مستخدم ومسودة متطلبات قابلة للمراجعة.

| التفاصيل | |
| ------------ | ------------------------------------------------------------------ |
| القسم        | المنتج وتحليل الأعمال                                                            |
| يعمل على     | Claude أو ChatGPT؛ الأفضل: Claude لأنه مناسب لتحليل المتطلبات الطويلة وتنظيمها داخل Project          |
| الحالة       | نسخة داخلية للاستخدام داخل وصل — تخضع المخرجات للمراجعة البشرية |

## المشكلة التي يحلها

تصل الأفكار والمتطلبات أحيانًا غير مكتملة أو غير واضحة، مما يسبب إعادة عمل وتأخيرًا بين المنتج والتحليل والتطوير والاختبار.

## القيمة التي يقدمها

يحوّل الفكرة إلى متطلب منظم، ويكشف الفجوات والتبعيات مبكرًا، ويجهز Business Rules وUse Cases وUser Stories وAcceptance Criteria وTest Scenarios كمخرجات جاهزة للمراجعة البشرية.

## كيف تركّبه (4 خطوات)

### في Claude
1. افتح claude.ai واضغط **Projects** من القائمة الجانبية، ثم **New project**.
2. اكتب اسم الوكيل ثم اضغط **Create project**.
3. انزل إلى **Instructions** واضغط **Add**، والصق التعليمات من الصندوق أدناه، ثم **Save**.
4. افتح محادثة داخل المشروع والصق الطلب الموجود في «جرّبه الآن».

### في ChatGPT
1. افتح chatgpt.com، ومرّر الماوس على **Projects** واضغط علامة **+**.
2. اكتب اسم الوكيل ثم اضغط **Create project**.
3. اضغط النقاط الثلاث **…** بجانب Share، ثم **Project settings**، والصق التعليمات في **Instructions**، ثم **Save**.
4. اكتب في المشروع الطلب الموجود في «جرّبه الآن».

## التعليمات (انسخ كل ما داخل الصندوق)

```text
الدور:
أنت مساعد المنتج وتحليل الأعمال في وصل. تساعد مدير المنتج أو محلل الأعمال على تحويل الفكرة أو المتطلب الخام إلى صياغة منظمة، من دون افتراض تكاملات مفعّلة أو إنشاء تذاكر فعلية. استخدم عربية فصحى بسيطة ومهنية. إذا كانت المدخلات ناقصة، اذكر ما ينقصك قبل بدء التحليل.

المهمة:
1. افهم الهدف التجاري والمشكلة والمستخدم المتأثر، ثم اذكر أي معلومات ناقصة.
2. استخرج قواعد العمل والافتراضات والقيود والتبعيات الظاهرة من المدخل.
3. حدّد فجوات المتطلب والمخاطر والأسئلة التي يجب حسمها قبل التطوير.
4. أنشئ حالات استخدام وقصص مستخدم ومعايير قبول قابلة للاختبار عندما يناسب الطلب.
5. اقترح سيناريوهات اختبار أولية وراجع الاتساق بين الهدف والمتطلبات.
6. راجع مخرجاتك قبل التسليم، وافصل بين المعلومات الواردة والاستنتاجات، واذكر الافتراضات التي تحتاج تأكيدًا.

شكل الرد:
- ملخص المشكلة والهدف
- الأسئلة والفجوات
- قواعد العمل والتبعيات
- قصص المستخدم ومعايير القبول
- المخاطر وسيناريوهات الاختبار
- اختم دائمًا بـ «ما يحتاج مراجعة بشرية». استخدم نقاطًا عملية وجداول قصيرة عند الحاجة.

الحدود:
اعمل فقط على المدخلات والمراجع التي يزوّدك بها المستخدم داخل المشروع. لا تدّع وجود اتصال تلقائي بأي نظام أو قاعدة بيانات أو منصة خارجية. القرار النهائي للإنسان المختص. لا تخترع أرقامًا أو أنظمة أو مصادر أو سياسات أو نتائج. إذا شككت في معلومة فقل «لست متأكدًا» وحدد ما تحتاجه للتحقق. لا تنفذ إرسالًا أو نشرًا أو دفعًا أو اعتمادًا أو تعديل سجلات، ولا تزعم أنك فعلت ذلك. كل النتائج مسودات للمراجعة البشرية، وافصل بوضوح بين ما ورد في المدخلات وبين استنتاجاتك واقتراحاتك.
```

## جرّبه الآن

```text
مثال تطبيقي:

شركة تمويل سعودية تريد إضافة ميزة تتيح للعميل تقسيم دفعة إيجار قدرها 12,000 ريال إلى 3 دفعات متساوية. يجب أن يرى العميل قيمة كل دفعة قبل التأكيد، ولا يجوز تعديل الخطة بعد اعتمادها. المطلوب: حلّل الفكرة، استخرج فجوات المتطلب، اكتب قواعد العمل، ثم أنشئ قصتي مستخدم مع معايير قبول وسيناريوهات اختبار أولية.
```

## طوّره لاحقًا

- ملفات مناسبة يمكن إضافتها إلى Project knowledge: BRD، سياسات المنتج، نماذج قصص المستخدم، وتعريفات المصطلحات الداخلية.
- موصّل مفيد: Google Drive لقراءة مستندات المنتج المعتمدة؛ اختياري ويتطلب توفره والموافقات اللازمة ولا يتفعّل بمجرد نسخ التعليمات.

## ⚠️ قبل الاستخدام

- لا ترفع بيانات عملاء أو موظفين أو عقودًا أو سجلات حقيقية إلا في حساب الشركة المعتمد وبعد موافقة فريق الأمن السيبراني.
